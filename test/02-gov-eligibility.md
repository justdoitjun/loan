# 02. 자격 화면 — 스텝 흐름 · 건너뛰기 · 실시간 요약 · 결과 카드

규칙: `ux.md` 3단계, `gov_common.md`, `architecture.md` 「판정 엔진 구조」.
코드: `src/Eligibility.jsx`, `src/eligibility/*.jsx`, `person.FLOW` · `flowOf` · `withSpouse` · `bucketOf` · `homeBucketOf`, `engine.deriveFacts` · `judgeAll` · `nearIncomeCap`.

숫자(한도·상한)는 [03-didimdol.md](03-didimdol.md)·[bank-mortgage.md](bank-mortgage.md)가 본다. 이 문서는 **스텝이 언제 열리고 사라지는지, 답이 어떻게 정리되는지, 요약과 결과를 어떻게 보여 주는지**를 본다.
정부/은행 탭은 없다. 한 번 답하면 전 상품(디딤돌 5종 + 보금자리 + 은행)이 한 목록에 뜬다.

## 준비

새로고침 → 소득 슬라이더 → 중계동 매물 하나 → Yes → 자격 화면.
따로 적지 않으면 소득 4,000만, 매물 `동진 38.79㎡`(2억 2,950만).

생년월일은 휠이다. 처음엔 비어 있고 가장 최근 해가 가운데에 있다 — 본인·배우자는 **올해 성년(만 19세)이 되는 해**(2026년 기준 2007), 자녀는 올해(2026). 2026·2025 같은 미성년 해는 본인·배우자 휠에 없다. **년을 누르면 그해 1월 1일**이 들어간다. 월·일은 그다음에 누른다.
밀고 손을 떼면 한 칸에 정확히 멈춘 뒤에만 값이 정해진다. 두 칸 사이에 걸친 채로 값이 바뀌면 실패다.
나이는 오늘(2026-10-12) 기준 만 나이다. 1990-01-01 = 만 36세, 1997-12-31 = 만 28세, 1987-01-01 = 만 39세, 1986-10-01 = 만 40세.

> **날짜 의존**: 다른 날 돌리면 위 나이가 같게 나오도록 생년월일을 옮긴다. 경계 케이스(GV-31·32)는 오늘과 같은 월·일로 맞춘다.

## A. 스텝 순서 (`flowOf`)

스텝: ① 가족정보 → ② 주택 보유 상태(4버킷) → ③ 생애최초(무주택만) → ④ 혼인상태(무주택만) → ⑤ 배우자 소득(합산 대상이 있을 때만) → ⑥ 청년 주택드림(무주택 + 만 39세 이하) → 결과.
한 화면에 스텝 하나. [다음]은 그 스텝을 답했을 때만 눌린다. [뒤로]는 한 스텝 앞으로, 첫 스텝에선 매물목록으로.
상단 요약 `지금 답으로 열린 대출 N개 · 최대 약 X억` + `앞으로 M개만 더`. 프로그레스 바는 없다(있으면 실패).

| ID | 우선 | 종류 | 상태 / 조작 | 기대 |
|---|---|---|---|---|
| GV-01 | P2 | 화면 | 처음 진입 | 가족정보 카드만. 요약 `0개`, `앞으로 2개만 더`(가족·주택. 뒤 스텝은 답에 따라 생긴다) |
| GV-02 | P1 | 화면 | 본인 생년월일만 넣음 | [다음]이 눌리지 않는다. 배우자 `있음/없음`을 골라야 열린다 |
| GV-03 | P1 | 화면 | 본인 1990 · `배우자 없음` → 다음 | `이렇게 보고 계산해요 / 만 36세 · 배우자 없음 · 자녀 0명(미성년 0명)` 뒤 주택 보유 스텝. 요약 `0개` |
| GV-04 | P1 | 화면 | `+ 자녀 추가`만 누르고 생일을 비워 둠 | [다음]이 닫힌다(가족정보 미완). 자녀를 넣거나 `삭제`하면 다시 열린다 |
| GV-05 | P1 | 화면 | 자녀 생일을 2026 → 11월 → 1일(미래) | 미래 날짜라 입력 완료로 보지 않는다. [다음]이 닫힌 채다 |
| GV-06 | P2 | 화면 | `배우자 있음` | 배우자 생년월일 휠(`몰라도 넘어갈 수 있어요`)이 열린다. 비워도 다음으로 간다 |

| GV-08 | P1 | 화면 | 주택 `없어요` → 다음 | 요약 `3개`(일반가구 · 보금자리 · 은행 — 36세 단독세대주라 일반가구 통과), `생애 처음으로 집을 사시는 건가요?` |
| GV-09 | P1 | 화면 | 생애최초 답 → 다음 | `결혼하셨나요?` 4버킷 |
| GV-10 | P1 | 화면 | `배우자가 없어요` → 다음 | 소득 스텝이 없다. 만 39세 이하면 청년 주택드림 스텝, 아니면 결과 |
| GV-11 | P1 | 화면 | 만 36세 · 배우자 없음 · 청년 질문 `아니오·해당없음` → 결과 보기 | `입력한 조건` 목록 + 결과 카드(디딤돌 일반가구 · 보금자리 · 일반 주택담보대출). 카드마다 정부/은행 꼬리표, 한도/금리/실행 3줄 |
| GV-12 | P1 | 화면 | 만 40세(1986-10-01) · 배우자 없음 | 청년 주택드림 스텝이 **없고** 혼인 뒤 바로 결과. `입력한 조건`에 `청년 주택드림` 줄이 없다 |
| GV-13 | P1 | 화면 | 만 39세(1987-01-01) | 청년 스텝이 있다. 답해야 결과 |
| GV-14 | P1 | 화면 | 주택 `집이 하나 있지만, 처분할 거예요`(배우자 없음) | 생애최초·혼인·통장 스텝을 **건너뛰고** 바로 결과. 은행 카드 1개(LTV 40% 일반차주). 요약 `1개` |
| GV-15 | P1 | 화면 | GV-14에서 `배우자 있음`이었다면 | 배우자 소득 스텝은 묻는다(DSR 합산). 은행 카드 설명에 배우자 소득 합산 기준이 적혀 있다 |
| GV-16 | P1 | 화면 | 결과에서 `입력한 조건`의 `결혼` 줄 | 혼인 스텝으로 돌아간다. 답은 그대로 선택돼 있다. 바꾸면 요약이 즉시 바뀐다(신혼 → 생애최초 신혼이 늘고, 배우자 없음 → 준다). 숨기지 않는다 |

## C. 배우자 소득 밴드와 정밀 입력 (`nearIncomeCap`)

밴드 대표값: `~3천` 1,500 · `3~5천` 4,000 · `5~7천` 6,000 · `7천~` 8,000(만원).
부부합산이 **어느 상품 소득상한의 ±1,000만** 안이면 `소득상한 경계 / 정확한 금액을 넣으면 더 좁혀요` 입력칸이 열린다.

| ID | 우선 | 종류 | 상태 / 조작 | 기대 |
|---|---|---|---|---|
| GV-40 | P2 | 화면 | 밴드를 고름 | `3천만원 ~ 5천만원 선택 · 계산은 구간 대표값 약 4,000만원으로 봐요…` |
| GV-41 | P1 | 화면 | 본인 5,000 + `3~5천` = 9,000 | 경계 입력칸이 열린다(신혼 8,500과 500 차이) |
| GV-42 | P1 | 화면 | 본인 2,000 + `~3천` = 3,500 | 입력칸이 **없다**(가장 가까운 상한 6,000과 2,500 차이) |
| GV-43 | P1 | 화면 | GV-41에서 정밀값 `3500` | 합산이 8,500으로 바뀌고 결과가 다시 계산된다. 요약 소득 줄 `본인 5,000만원 + 배우자 3,500만원` |
| GV-44 | P1 | 화면 | 정밀값을 넣은 뒤 밴드를 `5~7천`으로 바꿈 | 정밀값이 **지워지고** 대표값 6,000으로 계산 |
| GV-45 | P2 | 화면 | 정밀값을 넣어 경계에서 벗어남(예: `100`) | 입력칸이 닫히지 않는다(이미 넣은 값 유실 방지) |
| GV-46 | P2 | 화면 | 정밀값 `0` | 배우자 소득 0으로 계산. 맞벌이 플래그가 꺼진다(신생아는 외벌이 1.3억 상한으로 간다) |
| GV-47 | P3 | 화면 | 정밀값에 `-500` 입력 | 0으로 본다(`num`). 음수 합산이 되면 실패 |

## D. 세대주 추정 안내 (노랑)

세대주는 묻지 않는다. 기혼이거나, 배우자 없는 만 30세 이상이거나, 만 30세 미만 미혼인데 미성년 자녀가 있으면 세대주로 본다.

| ID | 우선 | 종류 | 상태 | 기대 |
|---|---|---|---|---|
| GV-50 | P1 | 화면 | 만 36세 · 배우자 없음 · 자녀 없음 · 미혼 | 결과 위 `단독세대는 상담역이 확인해요` (`만 30세 이상 단독세대로 보고 계산했어요…`) |
| GV-51 | P1 | 화면 | 만 28세(1997-12-31) · 배우자 없음 · 자녀 없음 | `세대주 요건이 아직 안 잡혀요` / `만 28세, 부양가족 없음. 미성년 형제·직계존속을 6개월 이상 부양하면 열릴 수 있어요.` 일반가구는 `안 열린 대출`에 세대주 조건으로 |

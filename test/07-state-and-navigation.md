# 07. 사람상태 · 탭 공유 · 뒤로 가기 · 목록 재계산

규칙: `architecture.md` 「사람상태 vs 화면상태」, `ux.md` 4단계(뒤로 가면 가정을 비운다) · 「화면 경계 원칙」.
코드: `App.jsx`(`person`, `clearStrategy`, `pickKind`, `swapUnit`), `person.personReady` · `eligReady` · `bankReady`, `verdict.judgeUnit`.

**사람상태** = `{ ownIncome, elig, detail, pull, incomeCheck }`. 매물을 바꿔도 남는다.
**화면상태** = `{ step, unit, kind, pickedKey, modalUnit, place }`. 지금 어디를 보고 있는지만.
예외: 방법 화면의 부채 확정과 손잡이(`detail`, `pull`)는 뒤로 가면 비운다.

## A. 매물·지역이 바뀌어도 사람은 남는다

| ID | 우선 | 종류 | 조작 | 기대 |
|---|---|---|---|---|
| X-01 | P1 | 화면 | 정부 탭을 끝까지 답함(매물 A) → `매물목록으로` → 매물 B → Yes → 정부대출 | 질문을 다시 묻지 않는다. `입력한 조건`이 접힌 채 B의 결과가 바로 뜬다 |
| X-02 | P1 | 화면 | X-01 상태에서 은행대출로 들어감 | 은행 탭은 정부 답(무주택·생애최초·배우자)을 쓴다. 정부 탭에서 배우자 소득까지 답했으면 은행 질문 없이 카드 |
| X-03 | P1 | 화면 | 지역을 다른 구·동으로 바꿈 | 연소득과 자격 답이 그대로. 정밀 모드였으면 새 동의 목록도 정밀 숫자 |
| X-04 | P2 | 화면 | 자격 화면에서 위 탭 정부 ↔ 은행 | 답이 지워지지 않는다. 접힘/펼침은 탭마다 따로 |
| X-05 | P2 | 화면 | 새로고침 | 모든 답과 소득이 처음으로 돌아간다. 저장하지 않는 것이 지금 설계다(브라우저 저장소 없음) |

## B. 대략 ↔ 정밀 전환 (`personReady = eligReady || bankReady`)

| ID | 우선 | 종류 | 상태 | 목록 모드 |
|---|---|---|---|---|
| X-11 | P1 | 로직 | 아무것도 답하지 않음 | 대략(`evaluate`, 본인 소득·40%·4%) |
| X-12 | P1 | 로직 | 정부: 가족정보 + 무주택 `아니오` | 대략. 게이트가 닫혀 정부 답은 "완료"가 아니다 |
| X-13 | P1 | 로직 | 은행: `계속 갖고 있을래요` 또는 `둘 이상` | 대략. 은행이 닫혀 은행 답도 완료가 아니다 |
| X-14 | P1 | 로직 | 은행: `없어요` · 생애최초 답 · `본인 소득만` | 정밀 |
| X-15 | P1 | 로직 | 은행: `처분할 거예요` · `본인 소득만` | 정밀(생애최초를 묻지 않고 완료) |
| X-16 | P1 | 로직 | 정부: 만 39세 이하인데 청년 질문만 안 답함 | 대략(정부 미완). 은행도 안 답했으면 그대로 대략 |
| X-17 | P1 | 화면 | 정부를 끝낸 뒤(정밀) 은행 탭에서 `계속 갖고 있을래요`를 누르고 목록으로 | 목록이 **대략으로 돌아간다**. 정부 게이트도 같이 닫히고(1주택) 은행도 닫혔기 때문. 숫자가 다시 바뀌는 것이 맞다 |
| X-18 | P1 | 화면 | 정밀 목록의 숫자 출처 | 정부+은행 전체 통과 상품 중 한도가 가장 큰 것. 방공제는 상품 기본값(디딤돌 차감, 은행·보금자리 상쇄). 부채는 확정 전이면 0. 은행만 답한 사람에게 보금자리 숫자가 나오는 문제 → **F-02** (FS-31) |

## C. 뒤로 가기

| ID | 우선 | 종류 | 조작 | 기대 |
|---|---|---|---|---|
| X-21 | P1 | 화면 | 방법 화면에서 부채 확정 + 손잡이 + 방공제 네 → `가능한 대출 목록으로` | 자격 답 그대로. 부채 확정·손잡이·방공제가 **비워진다**. 같은 카드로 다시 들어가면 `대출 없이 확정할게요`부터 |
| X-22 | P1 | 화면 | 자격 화면에서 `매물목록으로` | 자격 답·연소득 그대로. 부채·손잡이 비움. 목록은 무부채 정밀 숫자 |
| X-23 | P2 | 화면 | 방법 화면 → 뒤로 → 다른 상품 카드 | 새 상품 방법 화면. 앞 상품에서 확정한 부채가 남아 있으면 실패 |
| X-24 | P2 | 화면 | 매물 팝업에서 `닫기` | 목록 그대로. 사람상태 변화 없음 |

## D. 같은 사람상태를 여러 화면이 같이 읽는다

| ID | 우선 | 종류 | 조작 | 기대 |
|---|---|---|---|---|
| X-31 | P1 | 화면 | 방법 화면에서 신용 손잡이를 움직이며 `인근 다른 매물`을 펼쳐 봄 | 다른 매물 자본금이 손잡이와 **같이** 바뀐다. 손잡이 값이 화면 로컬 상태로 내려가면 여기가 안 움직인다(`architecture.md` ⚠️) |
| X-32 | P1 | 화면 | 정부 답 완료 후 목록에서 소득을 6,000 → 6,100 → 매물 → Yes → 정부 | 30세+ 단독 일반가구가 `안 열린 대출`로 내려가고 `소득 100만원 초과`. 자격은 매번 다시 계산한다(결과를 들고 다니지 않는다) |
| X-33 | P2 | 화면 | X-32 후 접힌 요약 | `소득` 줄이 `본인 6,100만원만` |
| X-34 | P1 | 로직 | `judgeUnit(매물, 사람)`을 같은 입력으로 두 번 | 결과가 같다. React·화면 없이 node에서 돈다. 단 나이·신생아는 `new Date()`를 쓰므로 날짜가 바뀌면 달라진다 |
| X-35 | P1 | 로직 | 방법 화면 숫자 vs 목록 숫자 (같은 상품·같은 가정) | 같은 `leverOf` → `limitAt`. 방공제만 다르다(방법 화면은 아니오 기본, 목록은 상품 기본). 차이가 5,500만을 넘거나 방공제와 무관한 차이가 나면 실패 |
| X-36 | P1 | 로직 | 소득 가정이 자격을 닫는 경우(목록 vs 방법 화면) | 목록은 가정 소득으로 자격을 다시 판정한다. 방법 화면은 고른 상품을 원래 소득으로 판정한다. 둘이 갈리는 사례 → F-04 |

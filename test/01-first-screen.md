# 01. 첫 화면 — 지역 · 연소득 · 매물 목록 · 소득 확인 · 팝업

규칙: `ux.md` 「화면 흐름」 1~2단계, `_policy.md`(예산 화면 LTV·지역 cap), `architecture.md` 「사람상태 vs 화면상태」.
코드: `src/App.jsx`, `src/Home.jsx`, `src/reveal.js`, `engine.evaluate`, `engine.affordablePrice`, `verdict.judgeUnit`, `src/geo.js`.

## 준비

`npm run dev` → `http://localhost:5173`. 케이스마다 새로고침한다(사람상태가 남는다).
첫 지역은 **서울특별시 > 노원구 > 중계동**, 연소득은 **5,000만**, 보유 현금은 **2억 9,500만**이다(`data.REVEAL`).

자격 전 목록의 계산(본인 소득만):

```
대출 = max( min( 시세 × 40% − 5,500,  DSR 40%·4%·30년(본인 소득),  지역 cap ), 0 )
자본금 = 시세 − 대출
구간 = 자본금 ≤ 현금 → 초록 / 자본금 − 현금 ≤ 시세 × 10% → 노랑("약 X 부족") / 그 밖 → 회색(접힘)
```

목록은 **단지당 한 행**이다. 대표 평형 = 현금 안에 드는 평형 중 가장 넓은 것, 없으면 가장 덜 모자란 것.
정렬은 초록 → 예산선 → 노랑 → 회색(접힘) 블록 순, 각 블록 안에서 대표 평형의 **시세 높은 순**(같으면 자본금 적은 순). 맨 위 초록 행에 "1등" 배지. 구간·접기·대표 평형은 `src/reveal.js`.

## D. 대략 → 정밀 전환

자격 스텝을 끝까지 답하면(`personReady` = `flowOf(elig).ready`) 목록이 `engine.evaluate` 대신 `verdict.judgeUnit`으로 바뀐다.
정밀 숫자는 **전체** 상품 중 한도가 가장 큰 것이다. 상품 기본 방공제를 쓴다(디딤돌 차감, 은행·보금자리 상쇄).

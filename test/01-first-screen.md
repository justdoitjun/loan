# 01. 첫 화면 — 지역 · 연소득 · 매물 목록 · 소득 확인 · 팝업

규칙: `ux.md` 「화면 흐름」 1~2단계, `_policy.md`(예산 화면 LTV·지역 cap), `architecture.md` 「사람상태 vs 화면상태」.
코드: `src/App.jsx`, `engine.evaluate`, `verdict.judgeUnit`, `src/geo.js`.

## 준비

`npm run dev` → `http://localhost:5173`. 케이스마다 새로고침한다(사람상태가 남는다).
첫 지역은 **서울특별시 > 노원구 > 중계동**, 연소득은 **0원**이다.

자격 전 목록의 계산(본인 소득만):

```
대출 = max( min( 시세 × 40% − 5,500,  DSR 40%·4%·30년(본인 소득),  지역 cap ), 0 )
자본금 = 시세 − 대출
```

## D. 대략 → 정밀 전환

자격 답을 마치면(`personReady` = 정부 **또는** 은행 답변 완료) 목록이 `engine.evaluate` 대신 `verdict.judgeUnit`으로 바뀐다.
정밀 숫자는 정부+은행 **전체** 상품 중 한도가 가장 큰 것이다. 상품 기본 방공제를 쓴다(디딤돌 차감, 은행·보금자리 상쇄).

| ID | 우선 | 종류 | 조작 | 기대 |
|---|---|---|---|---|
| FS-30 | P1 | 화면 | 소득 4,000만, `현대그린 84.99㎡` → 은행 → `없어요` → `아니오` → `본인 소득만` → `매물목록으로` | 현대그린이 **1억 9,300만 → 2억 41만**으로 바뀐다(40% 상쇄 2억 4,800만과 DSR 7% 2억 41만 중 작은 값). 보금자리는 6억 초과라 닫힌다 |
| FS-31 | P1 | 화면 | 같은 상태에서 `성원2 84.78㎡`(5억 6,300만) | **기대(규칙)**: 은행 카드와 같은 2억 41만. **현재**: 3억 6,000만(보금자리 cap) → **F-02** |
| FS-32 | P1 | 화면 | 새로고침. 정부 탭에서 가족정보를 채우고 무주택 `아니오` | 닫힘 카드만 뜨고 결과는 없다. 목록으로 돌아가면 숫자가 **바뀌지 않는다**(정부 답이 끝나지 않았고 은행도 안 답함) |
| FS-33 | P2 | 화면 | 정밀 모드에서 소득 슬라이더를 4,000 → 6,000 | 목록이 즉시 다시 계산된다. 매물을 누르면 `소득 6,000만원으로 평가해볼까요?` |
| FS-34 | P2 | 화면 | 정밀 모드에서 다른 매물을 누르고 Yes → 은행 | 은행 질문을 다시 묻지 않는다. 접힌 `입력한 조건`과 카드가 바로 나온다 |
| FS-35 | P2 | 화면 | 정밀 모드 전·후로 화면에 안내가 있는지 | 지금은 전환 안내(`PreciseNote`)가 주석이라 없다. 숫자만 바뀐다. `architecture.md`는 "전환 시 목록의 대출·필요 현금이 바뀌는 게 사건"이라 한다 — 안내 없이 바뀌는 것이 의도인지 확인 |

# Claude QA 산출물 (2026-10-12)

역할: QA 엔지니어 + 프로덕트 디렉터. 범위: `./test`의 QA 문서 전부와, 그 문서가 놓친 구멍.
**코드는 바꾸지 않았다.** 이 폴더(`test/claude/`)에 파일을 더했을 뿐이다. `npm run build`가 `dist/`를 다시 만들었지만 git 추적 대상이 아니다.

## 결론

- **기존 QA 문서의 예고는 정확했다.** `→ F-xx`로 "지금은 실패"라고 적힌 케이스는 전부 그대로 실패했다. 통과로 적힌 숫자도 로직 112건이 같았다.
- **그 문서가 틀린 곳은 하나다.** `07` X-16. 정부 탭에서 `배우자 없음`을 고르면 은행 답이 저절로 완료되어, 결혼 질문 단계에서 이미 정밀 모드다(N-04).
- **새로 찾은 결함은 12개다.** 사용자 영향이 큰 순서:
  - **N-01 (높음)**: 기혼자가 은행 탭에서 `본인 소득만`을 누르면 정부 탭 결혼 답이 지워진다
  - **N-04**: 정부 질문 도중에 목록이 보금자리 숫자로 바뀐다
  - **N-02**: 같은 화면인데 방공제 토글 이력에 따라 다른 매물 숫자가 5,500만 바뀐다
  - **N-03**: 디딤돌 방공제 `네`에서 열 수 있는 손잡이를 숨긴다
  - **N-08**: 막혔을 때 "이 길에선 여기까지예요"와 다음 길이 없다
  - **L-01**: 320px에서 시세 숫자가 `13.…`으로 잘린다
  - **N-05**: 미성년도 대출이 열린다
  - 나머지는 낮음: N-06 · N-07 · N-09 · N-10 · B-05
- 근본 원인은 몇 곳으로 모인다.
  1. 진입 조건이 무주택 하나뿐인 보금자리 스텁을 목록 계산에 그대로 쓴다 (F-02, N-04, N-05)
  2. `hasSpouse`/`marital` 필드 하나를 정부(가구 구성)와 은행(합산 선택)이 다른 뜻으로 같이 쓴다 (F-01, F-14, N-01)
  3. 방공제 `null`의 뜻이 방법 화면(차감)과 목록(상품 기본)에서 다르다 (F-03, N-02, N-03)

## 다시 돌리기

```bash
node test/claude/scripts/cases.mjs    # 112/127 pass, 15 fail (14 결함 + X-16 문서 오류)
node test/claude/scripts/probe.mjs    # 5/13 pass, 8 fail (신규 결함)
npm test                              # 2 failed (F-10)
```

- 나이·신생아는 `new Date()`를 쓴다. 다른 날에는 결과가 바뀐다(DG-17/18/28/29/42/43).
- 결함을 고치면 해당 줄이 FAIL에서 PASS로 바뀌도록 짜 두었다. 기대값은 규칙 문서 기준이다.

## 하지 않은 것

- 화면 케이스 중 지역 시트, 생년월일 휠 세부, 키패드, 접기/고치기, 키보드 포커스(LY-21~26)는 브라우저로 누르지 않았다. `results.md`에 `—`로 남겼다.
- 배치 export(B-03, DA-31~33)는 DB가 없어 돌리지 않았다.
- 320px은 Chrome 창이 584px 밑으로 줄지 않아 320×667 iframe으로 봤다. 실제 기기 확인은 남아 있다.

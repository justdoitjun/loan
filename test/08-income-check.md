# 08. 소득 자가진단 (`IncomeCheck`)

규칙: `ux.md` 「화면 경계」 — 소득 신뢰도(초록/노랑)는 `IncomeCheck` 한 곳이고 **한도 숫자는 깎지 않는다**. `didimdol.md` 4절 · 5절(인정소득을 한도에 반영할지 보류).
데이터: `src/data/incomeRules.js`(원문 보존본), 화면은 `ACTIVE_INCOME_TYPES`(`supported: false` 제외).
코드: `src/IncomeCheck.jsx` `incomeCheckResult` · `incomeCheckReady` · `visibleChecklist`.

> 지금은 화면 입구가 없다(F-11). 아래 케이스는 **로직**으로 돌리고, 입구를 되살리면 같은 순서로 화면에서 확인한다.
> 로직 실행: `IncomeCheck.jsx`는 JSX라 node로 바로 import되지 않는다. 판정 함수를 뽑아 돌리거나, 개발 서버에서 `step`을 `incomeCheck`로 바꿔 화면으로 본다.

## 케이스

| ID | 우선 | 종류 | 입력 | 기대 |
|---|---|---|---|---|
| IC-01 | P1 | 로직 | 그룹 목록 | `소득 증빙이 어려워요`(estimated)가 **없다**. 원문 `INCOME_TYPES`에는 2종이 남아 있다 |
| IC-02 | P2 | 화면 | `일용직이에요` · `사업을 해요` · `그 외 소득이에요` · `지금은 소득이 없어요` | 유형이 하나라 세부 선택 없이 바로 질문(또는 결과) |
| IC-03 | P2 | 화면 | `회사에 다니고 있어요` | `② 좀 더 정확히는요?`에 4개. 질문 섹션 제목은 `③ 몇 가지만 더요` |
| IC-04 | P1 | 로직 | 일용직, `proof` = `네, 낼 수 있어요` | **노랑**(기본 노랑은 답과 무관). 노트가 있으면 노트, 없으면 `이 소득 유형은 산정 방식 자체가 입력한 금액과 달라요.` |

# 은행 일반 주택담보대출 판단기준

> 코드: `src/products/bank.js`(진입 조건·상한 없음) · `data.PRODUCTS.bank`(금융 파라미터) ·
> `src/eligibility/bank.jsx`(화면). 공통(Min 구조 · LTV 표 · 지역별 cap · 잣대 두 개)은 `_common.md`,
> 정부 정책값(지역 가정 · 방공제액)은 `_policy.md`. 코드와 어긋나면 **이 문서를 먼저 고치고 코드를 맞춘다.**
>
> ✅ 원문 확인 / ⚠️ 가정치(현직 판단 대기)

---

## 0. 판정 순서

```
① 진입 조건 — 주택 보유 상태 (LTV 표의 어느 행인가)
② 상한 검사 — 없음 (소득 · 가격 · 면적 상한이 없다)
③ 한도 = Min( LTV기반, DSR기반, 지역별 cap )
```
정부상품과 다른 점: **자격은 거의 없고 담보·상환능력이 전부다.**
상품별 cap이 없다(`cap: null`) → `_common.md`의 **지역별 cap**이 그 자리를 대신한다(`regionCapped: true`).

---

## 1. 진입 조건 — 주택 보유 상태 ✅ (`_common.md` LTV 표)

지역 = **규제지역 외 수도권**(`REGION = "metroOther"`, 노원 스냅샷 가정 → `_policy.md`).

| 보유 상태 | 플래그(`deriveFacts`) | LTV | 처리 |
|---|---|---|---|
| 무주택 | `noHome` | 70% | 열림 |
| 1주택 · 처분조건부 | `disposing` | 70% | 열림 — 처분 약정 이행은 상담역 확인 |
| 1주택 · 유지 | `oneHome` and not `disposing` | **0%** | 닫힘 — "처분조건부로 바꾸면 열려요" |
| 2주택 이상 | `multiHome` | **0%** | 닫힘 |

- 생애최초(70%) · 서민실수요자(60%)는 **이 지역에선 무주택 70%보다 유리하지 않아** 티어를 두지 않는다.
- ⚠️ 지방(80%) · 규제지역(40%) 행은 미구현. `REGION`을 바꾸면 `PRODUCTS.bank.LTV`도 같이 바꿔야 한다
  (지금은 단일값 0.70 — 표 전체를 코드로 옮기지 않았다, 정정 범위를 수도권 스냅샷으로 한정).

**질문은 둘뿐이다** — ① 주택 보유 상태 ② 배우자 소득(DSR 합산용).
가족정보 · 생애최초 · 결혼 · 청년통장은 묻지 않는다(은행 주담대에 안 쓰인다).
답은 정부탭과 같은 `elig` 한 벌에 들어간다(`homeCount` · `disposeExisting` · `hasSpouse` · `spouseBand`) —
한 탭에서 답하면 다른 탭에서 다시 묻지 않는다.

## 2. LTV와 방공제

| 항목 | 값 | 코드 |
|---|---|---|
| LTV | 70% | `PRODUCTS.bank.LTV` |
| 방공제 | **MCI 가입으로 상쇄** | `offsetsRoomDeduction: true` |

⚠️ MCI 가입 가능 여부(보증 한도·물건)는 상담역 영역. 화면은 "상쇄된다"로 계산하고 노랑을 붙이지 않는다 — 은행 관행상 기본이라서.

---

## 3. 상환능력 = DSR ⚠️ (차주단위 40%)

```
DSR(%) = ( 본건 연간 원리금 + 기존 부채 연간 원리금 ) / 연소득 × 100  ≤ 40%
```

| 항목 | 값 | 코드 | 비고 |
|---|---|---|---|
| DSR 상한 | 40% | `PRODUCTS.bank.ratio` (= `RULE.DSR`) | 은행 차주단위 |
| 본건 산정만기 | 30년 | `PRODUCTS.bank.years` | ⚠️ 실제 만기(최장 40년)를 안 묻고 30년으로 고정 |
| 본건 환산금리 | 4.0% + **스트레스 1.5%p** | `calcRate` (= `RULE.loanRate`) + `stressRate` | ⚠️ 수도권 3단계 스트레스 DSR 가정. **계산 전용** — 화면 금리(`rateLabel`)와 별개 |
| 기존 부채 환산 | 잔액 ÷ 5년 + 잔액 × 5.5% | `engine.annualDebtService` (`RULE.creditYears` · `RULE.creditRate`) | ⚠️ 신용대출 5년 분할 가정 |
| 부채를 보는 법 | **원리금 전체** | `DEBT_VIEW.bank = "principalAndInterest"` | 디딤돌(이자만)과 다른 점 |

- **소득**: 차주단위가 원칙. 배우자 소득을 합산하면 **배우자 부채도 합산**된다 →
  화면은 "배우자 소득을 넣었으면 부채 슬라이더에도 배우자 대출을 같이 넣으세요"로 안내한다.
  결혼예정자(예비배우자)는 합산 대상이 아니다 — 정부탭에서 `planned`로 답했으면 요약에 표시만 한다.
- **부채 잔액 하나로 충분한가** — MVP는 충분하다고 본다(5년 분할 가정이 잔액만으로 원리금을 만든다).
  마이너스통장 · 카드론 · 전세대출 구분은 상담역 영역. 부족해지면 **은행 경로에서만** 입력을 늘린다.
- 여기가 **부채 레버가 실제로 살아나는 경로**다 — DSR은 원리금 전체를 보므로 잔액 1,000만 감소가
  연 상환액 255만(=1000/5 + 1000×5.5%)만큼 한도를 연다. 디딤돌은 이자 53만만 열린다.

## 4. 지역별 cap ✅ (`_common.md` 표)

코드: `data.REGION_CAP`(표 그대로) + `engine.regionCapOf(price)`. 은행만 `regionCapped: true`.
정부상품은 제한 없음(플래그 없음 → `parts`에서 빠진다).
`_policy.md`의 옛 `RULE.seoulCap`은 이 표로 대체됐다 — 예산 화면 천장(`engine.evaluate`)도 같은 함수를 쓴다.

## 5. 금리 · 실행시점 ⚠️

| 항목 | 값 | 코드 |
|---|---|---|
| 표시 금리 | "연 4%대" | `rateLabel` — 계산엔 안 쓴다(계산은 3절 `calcRate`) |
| 실행 | 약 2~4주 | `leadTime` — 정부상품 ~2개월 대비 빠름. 잔금일 축의 갈림점 |

## 6. 검증 대기 목록

| 항목 | 상태 |
|---|---|
| DSR 산정만기 30년 고정 vs 실제 만기 입력 | ⚠️ 질문을 안 늘리려고 고정. 40년 만기면 한도가 약 15% 더 나온다 — 현직 판단 |
| 스트레스 금리 1.5%p | ⚠️ 시행 단계·지역에 따라 바뀜. 정책 갱신 대상 |
| 기존 부채 5년 분할 · 5.5% | ⚠️ 대출 종류별 실제 DSR 산정 관행과 대조 |
| MCI 상쇄 기본 적용 | ⚠️ 가입 불가 물건이면 방공제 차감으로 되돌아간다 |
| 처분조건부 1주택 = 70% | ✅ 표 / ⚠️ 처분 기한(6개월) 안내는 상담역 |
| 지방 · 규제지역 LTV 행 | 미구현 (1절) |

## 7. 코드 매핑

| 규정 | 코드 |
|---|---|
| 진입 조건(주택 보유 상태) | `src/products/bank.js` `requires: [["noHome","disposing"]]` · 플래그는 `engine.deriveFacts` |
| 상한 없음 | `incomeCap`·`priceCap`·`loanCap` 값 `null` → `engine.judgeRule`이 검사에서 뺀다 |
| Min(LTV, DSR, 지역별 cap) | `engine.limitParts` — `cap: null`이면 상품 cap 항이 빠지고 `regionCapped`면 지역 cap 항이 붙는다 |
| 화면 | `src/eligibility/bank.jsx` — 질문 2개 → 카드(한도 / 금리 / 실행시점 + 무엇이 벽인가) |
| 진행 상태 | `person.bankSteps` — 지도 정밀 모드는 정부 **또는** 은행 답변이 차면 켜진다(`personReady`) |
